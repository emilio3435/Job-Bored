Narrow: one column, same order

Every threshold below is a container query on the dossier frame, never a media query on the window. That is the fix for the shipped layout's central bug: it switches on max-width: 1080px of viewport, which is why it is correct at 1024 and broken at 1440 — a 1080px window still only gives each of three lanes 323px of text. Source order never changes, so the tab order and the reading order stay the same at every width.

1024 · 32px above the 62rem threshold — the tightest two columns get: ledger at its 20rem floor, canvas 586px

900 · below the threshold — one column, ledger follows the canvas, docket still sticky

720 · masthead flags wrap to their own row, metrics reflow to two-up

390 · phone. Metrics two-up, stepper scrolls, materials rows fully stacked, nothing truncated
