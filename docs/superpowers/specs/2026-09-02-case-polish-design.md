# The Case — Polish Pass Specification

**Date:** 2026-09-02
**Status:** Proposed — awaiting confirm
**Scope:** defects in what PRs #87 and #91 shipped. No new features, no redesign.
**Source of findings:** five parallel read-only Opus 5 audits (render correctness, CSS/display, a11y/interaction, copy/honesty, data pipeline), 2026-09-02. Every item below was verified in the source by the orchestrator before it entered this spec.

---

## 1. What this fixes

The Case shipped correct in structure and green on every gate, but the audits found three classes of defect the test suite structurally could not see:

- **Keyboard and screen-reader paths** — the harness drives everything with `.click()` and has no key handling, so keyboard-only regressions are invisible to it.
- **Copy that leaked the pipeline** — internal enum values and reliability-legend vocabulary reaching the screen.
- **States nobody rendered** — captions that contradict their own number, tiles the spec said to hide, severities nobody assigned.

Governing rule for this pass: **every change is a defect fix traceable to a spec line or a broken user path.** Where the spec is silent, the fix is the one that tells the truth about the data.

## 2. P0 — data loss, lies, and spec violations

| # | Defect | Where | Fix |
|---|---|---|---|
| P0-A | **One role's AI analysis is shown on other roles.** The scorecard key is built from `origin + pathname` and throws the query string away, so every Indeed `viewjob?jk=…` and every LinkedIn `jobs/search?currentJobId=…` collapses to the same key. `getScorecardForJob` returns whichever such role was scored last, and the Case renders its strengths, evidence quotes, critical gaps and dimension bars under an `ai · scorecard` tag with no identity check. Path-based boards (Greenhouse, Lever) are unaffected; two of the most-pasted sources are not. | `materials-state.js:89-111`, `user-content-store.js:137-160` | Keep the query string (or the known id params) in the key, and store the scored job's title+company so a mismatch is rejected. |
| P0-B | **A stale `validThrough` prints "Closed 305 days ago" next to "Posting open".** The closes pill admits arbitrarily negative values, while `getPostingHealth` returns "open" for any active row with an http link — it has verified nothing. Both render into the same pill row. Greenhouse and LinkedIn mirrors routinely carry a `validThrough` ~30 days after posting on roles that stay live for months. | `role-case.js:26-27, 60-70`, `expired-review.js:100-105` | Suppress the pill below ~-30 days; never show "open" beside a past close date. |
| P0-C | **Posted salary can mislead three ways.** A min-only or max-only figure renders as an exact number ("up to $220k" → `$220,000 USD/yr`); the currency is read only from `baseSalary.currency`, so nested or JobPosting-level currency yields a bare `180,000–220,000/yr`; and an unmapped `unitText` (DAY, WEEK — common on contract roles) silently drops the period, so `$800` sits on the rail beside annual sheet salaries. | `server/shared/job-scraper-core.mjs:1002, 1011-1020` | Prefix From/Up to; read the nested and JobPosting-level currency; add WEEK/DAY and fall back to "per <unit>". |
| P0-D | **One corrupt byte destroys every stored scorecard, and a null entry turns a successful analysis into an error.** A `JSON.parse` failure returns `{}` and the next write silently overwrites up to 99 entries; the LRU comparator dereferences `storedAt` unguarded, and because the write happens inside the scorecard's success `try`, the throw flips a finished analysis to `status: "error"`. Quota exhaustion and private browsing are both swallowed, so the scorecard is silently re-paid for every session. | `materials-state.js:116-154`, `ats-scorecard.js:527-551` | Guard the comparator, drop the key on a parse failure rather than overwriting, and warn on the quota path. |
| P0-E | **Six silent catches, two of which fail toward over-confidence.** A throw in `getScorecardForJob` makes the entire "You have" lane vanish with no trace; a throw in the provenance classifier clears `inferredFields`, so a title the model guessed renders identically to one read from the posting — the opposite of the stated design intent. Neighbouring code does warn, so these are the outliers. | `role-case-model.js:180, 193, 267-275` | Warn in all six; on a provenance throw keep the inferred tag rather than clearing it. |
| P0-0 | **The requirement marks are almost always `unknown` — the THEY WANT lane's entire purpose.** The model looks up the *full requirement string* in `keywords.byLabel`, but the analyzer only ever stores **fragments** (it splits long requirements on `;,|`/`and`/`or`, skips whole items over 8 words, and truncates any label over 72 chars). So only single-token items like "React" ever mark; every real sentence-shaped requirement renders a grey `unknown` dot while the lane head still claims `matched` and `vs. your resume`. Verified end-to-end against the real `analyzeJob` with a resume that clearly matches. | `role-case-model.js:43-48, 214-216` | Match a requirement when any analyzer term is contained in it (or vice versa) after normalization; take the strongest status among matching terms. Keep `unknown` only when nothing overlaps. |
| P0-0b | **Opening role B paints role A's materials rows.** `rehydrateOpenRole()` repaints a module-global `lastPaint` that is cleared only on `jb:role:closed` — which never fires when switching directly between roles. The Materials *tile* correctly disappears (the model key-guards the manifest) while the *rows* still list the previous role's files and download links. | `role.js:166-168`, `role-materials.js:905-914` | Key the repaint to the open role; skip when it does not match. |
| P0-0c | **A scorecard that was never scored renders as `ATS 0/100` and five 0% bars.** `scoreOf(null)` returns 0 (`Number(null) === 0`), and the scorecard writer already flattens missing scores to 0 before persisting — so "not scored" is indistinguishable from "scored zero", persisted across sessions. | `role-case-model.js:49` | Return null for null/undefined/blank input; hide the tile and the dimensions when there is no real score. |
| P0-0d | **Day counts are UTC, so they are a day early west of UTC.** A follow-up due Sep 4 reads "today" at 18:30 MDT on Sep **3**, and "1d overdue" on the actual due day. Affects the follow-up pill, the closes-soon pill, and its ≤14-day promotion. Both suites pin a UTC noon "now", which cancels the error out. | `role-case-model.js:64, 88-92` | Compare local calendar days, not raw millisecond deltas. |
| P0-1 | **Enter is dead on the Replied chips.** `role.js` binds a `keydown` handler to every `[data-action="edit-field"]`, which matches the three Replied `<button>`s. On a button, click *is* Enter's default action, so `preventDefault()` cancels it: no click, no writeback. Space and mouse work, which is why it survived review. | `role.js:311-331` | Bind the Enter/Escape handler only to surfaces with a text value; buttons commit through the click walker. |
| P0-2 | **Every post-action re-render dumps focus to `<body>`.** Activating a stage step cascades to `jb:pipeline:rendered` → `renderForKey` → `mount.innerHTML = …`, destroying the focused node. The guard only defers for edit surfaces, and a focused `<button>` does not match. A keyboard user is ejected to the top of the document mid-task. | `role.js:386-410`, `role-case.js:228` | Record the focused element's identity (`data-action` + `data-stage`/`data-field`) before the swap; restore focus to the matching node after render. |
| P0-3 | **`aria-pressed` lies after a reply write.** The write succeeds and "saved" announces, but nothing repaints the segment, so the chosen chip stays unpressed and the old one still reports `aria-pressed="true"` until the 5-minute poll. | `role.js:225-229` | Optimistically move the `--on` class and `aria-pressed` in the click handler before dispatching. |
| P0-4 | **The materials row prints a raw state-machine enum.** Rows render `rendering_pdf · 1m 04s · attempt 1`. `defaultPhaseMessage` already holds a human sentence for every phase. `attempt 1` also always shows, reading as "something already went wrong" — the legacy panel showed it only above 1. | `role-materials.js:705-707` | Map phase → plain words; show a retry count only above 1. |
| P0-5 | **The Materials tile contradicts its own number.** The caption branches only on `drafting`, so `0/4` is captioned "All ready". | `role-case.js:112` | Caption from `ready` vs `total`; count only rows the user can actually request. |
| P0-6 | **The Reply tile renders unconditionally**, so a role with nothing recorded shows a tile whose entire value is the word "Unknown". Spec §3 (Numbers band): "each tile hides when its input is absent." | `role-case.js:111` | Push the tile only when the reply value is Yes or No. |
| P0-7 | **The keyword fallback invents a severity.** With no scorecard, every fallback gap is hardcoded `severity: "medium"` and renders a `MED` pill — a judgement no engine made. Spec §3 (You have): "gaps = keyword missing terms **(no severity)**." | `role-case-model.js:130`, `role-case.js:162` | Emit no severity in the fallback; suppress the pill unless the source is the scorecard. |
| P0-8 | **An overdue follow-up renders as done.** The record marks a past follow-up `state: "done"`, so a missed date shows a completed dot under the label "Follow-up due". | `role-case-model.js:148` | A past follow-up with no contact after it stays `due`. |
| P0-9 | **`You have` can render as a bare heading.** The early return only fires on `source === "none"`; a keyword analysis whose terms are all `partial` yields no strengths and no gaps, so the lane emits a header and closes. Spec §3 says it hides when neither exists. | `role-case.js:156-166` | Hide when strengths, evidence, gaps and dimensions are all empty. |
| P0-10 | **Keyword-fallback strengths render lowercased analyzer fragments** ("wcag 2.2", "figma design systems") — the properly-cased `label` on each term object is discarded. | `role-case-model.js:124-127` | Use the term's own label, not the map key. |
| P0-11 | **The terminal stage chip prints the raw key** (`rejected`), while every non-terminal step goes through the registry's label. The render test's regex is case-insensitive, so it passes either way. | `role-case.js:91` | Use `stages.toLabel`. |

## 3. P1 — accessibility and display

| # | Defect | Where | Fix |
|---|---|---|---|
| P1-0 | **The Case card has no horizontal gutter below 1180px** — its rounded corners and border sit flush against both browser edges. The empty state in the same region *is* inset 32px, so selecting a role jumps the content from inset to edge-to-edge. It is the only v2 region not using `--jb-flow-content-width`. | `role-case.css:24`, `role.css:221-234` | Give `.case` the shared flow width (or a clamped side margin) and raise `.dossier`'s 1180px cap so the spec's 1240 is reachable. |
| P1-0b | **The numbers band is hardcoded to 5 columns but usually renders 2–4 tiles.** A role with no scorecard and no keyword match — the common first-open state — shows three tiles crammed into the left 60% with a blank strip running to the card edge. At ≤1080 the orphaned second row keeps a dotted border hanging at the container edge. The `data-count` hook the fix needs is already emitted and unused. | `role-case.css:71, 222, 231` | Drive the track count off `data-count`. |
| P1-0c | **The "saved" mark is effectively invisible** — mint-deep on parchment at 8px is **2.81:1**, and it fades in 1.6s. It is the only confirmation that an edit persisted. Same color fails on the ready-status pill (2.52:1), the evidence label (2.98:1), the derived source tag (2.98:1) and the scorecard bars (2.62:1, under the 3:1 non-text floor). | `role-case.css:187, 151, 120, 82, 131` | Darken the on-light mint to ≈#3F6B55; keep #6E9F87 only against navy. |
| P1-0d | **`--mute` fails 4.5:1 on both Case backgrounds** (4.34:1 on parchment, 4.04:1 on parchment-deep) and carries nearly every label in the dossier — the stage stepper, all section heads, all key/value labels, timeline dates — none of it large-scale, all 8.5–10.5px. | `role-case.css` (15 rules) | Use `--ink-soft` for these labels, or darken the token. |
| P1-0e | **A materials failure is indistinguishable from an empty shelf.** The error modifier is keyed to a class the Case never emits, so "Local materials server is unreachable" renders in the same muted italic as "nothing here yet". | `role-materials.js:820-822`, `role.css:1016` | Add a Case-scoped error rule (crimson, not italic). |
| P1-0f | **Two dead rules with visible effects**: `.case__stamp--fresh`'s `margin: 0` is overridden by the base rule declared 42 lines later (the freshness line sits 12px off its gutter, against its own comment's stated intent), and `.case__gap:last-of-type` never matches when a scorecard is present (a stray dotted rule hangs above "Scorecard dimensions"). | `role-case.css:91 vs :133`, `:122` | Reorder the first; use sibling handling for the second. |
| P1-0g | **"View posting" is the only pill with no hover**, and the clickable Keywords tile is visually identical to the four static tiles beside it. | `role-case.css:60, 74` | Extend the hover rule to the link; give the tile a hover state and a focus outline. |
| P1-1 | **The dossier has zero headings.** Lane titles are spans, the role title is an `<input>`. H-key navigation and the rotor return an empty list; the role's own name exists only as "Role title, edit text". | `role-case.js:81, 135, 159, 192, 218` | An `<h2>` carrying the role identity (visually hidden if it must not disturb the rail) and `<h3>` for each lane title. |
| P1-2 | **The stage stepper has no state or group semantics** — N identical buttons, current stage encoded only in a CSS class. | `role-case.js:94-101` | `role="group" aria-label="Stage"`, `aria-current="step"` on the current step, `aria-label="Move to <label>"` per button. |
| P1-3 | **Stack chips carry match status in color alone** — an empty colored dot, no text, unlike the requirement rows which do emit the word. Fails WCAG 1.4.1; screen readers get nothing. | `role-case.js:140` | Emit the same status text the requirement rows use (visually hidden is acceptable). |
| P1-4 | **Provenance chips are read aloud as jargon.** ~10 stray tokens per full read ("Fit sheet 8 slash 10", "Your moves ai sheet files"). | `role-case.js:11` | `aria-hidden="true"` on the chip; fold the source into the tile's own `aria-label`. |
| P1-5 | **Text edit surfaces delete the global focus ring.** `outline: none` at specificity (0,4,1) beats the app's `:focus-visible` rule, leaving a 1px dashed underline as the only focus signal — under the SC 2.4.11 threshold, and nearly invisible on the navy rail. | `role-case.css:29, 39, 167, 195` | Add explicit `:focus-visible` outlines to those surfaces. |
| P1-6 | **Hit targets below the floor.** Doc-action buttons ≈70×21px and 6px apart (fails even the AA 24px spacing exception); stepper steps ≈21px tall; rail fact inputs ≈14px tall. | `role-case.css:63, 156, 39` | Extend hit areas with the `::after` inset pattern already used by the Replied chips; raise the doc-action gap. |
| P1-7 | **The loading skeleton never announces.** The `role="status"` node and its text enter the DOM in the same `innerHTML` write, so no assistive tech fires. Same defect in the materials rows, whose live node is rebuilt every 3–12s poll. | `role-case.js:150-153`, `role-materials.js:719` | One persistent empty `role="status"` in the region shell, written into after render — the pattern the "saved" mark already gets right. |

## 4. P2 — copy that tells the truth

| # | Current | Problem | Replacement |
|---|---|---|---|
| P2-1 | `nextAction()` — four branches | No stage awareness (a Rejected role is told to "Follow up on 2026-09-04" beside its own "closed" chip); `contact === "Unknown"` short-circuits everything, so every New/Researching role gets "Find a recruiter contact" when the real move is to apply; the date is raw ISO; and the same sentence is labelled "Next action" on the card and "Next move" in the Case. | Stage-aware branch order: closed → nothing to do; overdue → "was due"; replied → get a time on the calendar; not applied → tailor and apply; else contact/date. One label: **Next move**. |
| P2-2 | `recovered parse · review` | "Parse" is about JSON, not the job. The user cannot act on schema-vs-repaired. | Tag → `unverified`; sub → "Read these against the posting before you rely on them". |
| P2-3 | `ATS` tile, always crimson | The acronym is never expanded anywhere in the product; crimson is the design's *missing/high-severity* color, so a 94/100 reads as bad news. | Label **Resume score**, sub "How well your draft answers this posting", crimson only when low. |
| P2-4 | Materials: `MISSING` / "not drafted" forever on two internal artifacts (`manual_apply_checklist`, `qa_report`) that have no draft action | They can never be produced from this UI; `role-materials.js` itself calls them "internal scaffolding … shouldn't crowd the Materials box". | Drop both from the Case rows (still reachable by URL); `missing` → **not yet**. |
| P2-5 | `failed` row with no actions | States a failure and offers no exit, unlike the legacy panel which offers retry and dismiss. | **couldn't finish** + the existing retry/dismiss buttons. |
| P2-6 | Materials empty state: "No tailored resume or cover letter on disk for this role yet." | "On disk" is machine vocabulary, and the Case branch returns before the invitation the legacy panel pairs with it. | "Nothing written for this role yet — use Draft cover letter or Tailor resume above to start one." |
| P2-7 | Source tags: `SHEET / SCRAPE / AI / DERIVED / FILES` | The engineering reliability legend, shipped as UI with no key. | from your sheet · from the posting · written by AI · matched here · your files |
| P2-8 | One concept, five names: "Profile match" (card + modal), "Keywords" (tile), "matched" (tag), "vs. your resume" (sub), "keyword match" (tag) | The tile is a button that opens the "Profile match" modal; control and destination don't share a name. | **Profile match** everywhere. |
| P2-9 | "Your agent's score"; "Enriched"; "Configured provider"; hardcoded "discovery" in every Found row | Names the pipeline, not the person; "Configured provider" is the *absence* of a provider rendered as one. | "How well this matched your search"; "Read by AI"; empty when unknown; drop the literal. |

## 5. Out of scope

The keyword fallback's *headings* ("Strengths"/"Gaps" for substring matches) and the materials/model status-ladder unification are real findings but touch shared contracts; they are recorded in the plan's follow-ups, not built here.

## 6. Contracts

Frozen: every `data-action` value, every `jb:*` event name and shape, `CASE_DOC_TYPES` as the model's export (its *contents* may lose the two internal types), `renderCompact` in `recruiter-strip.js` (kanban uses it), Sheet Interface A.

Tests updated, never weakened: `role-case-render`, `role-case-model`, `role-case-interactions`, `role-field-edit-render-guard`, `role-materials`, `dossier-provenance-labels`, `recruiter-strip-dossier`.

New: keyboard-path cases in `role-case-interactions` (Enter on a Replied chip dispatches; focus survives a re-render), and a `role-case-a11y.test.mjs` pinning headings, group semantics, `aria-current`, and non-color status text.

Floor: `npm test` · `lint:js` · `test:contract:all` · `typecheck:server` · `smoke:jb-v2` · `lint-tokens` · **both** Playwright suites.
