## What this changes

Replaces the Materials v2 "Readout" design from #117, which was rejected as archaic and document-y, with **Volt**: a new visual system *and* a new backend operating mechanism for resume + cover-letter generation. Specs, an implementation plan, fresh 3E mocks, one fixture per pipeline contract, six JSON Schemas, and two demonstration modules with tests.

[Readout (#117) beside Volt, same facts](https://cursor.com/agents/bc-3cbbfd22-285a-5db9-b3d0-e7072cb29fed/artifacts?path=%2Fopt%2Fcursor%2Fartifacts%2Fscreenshots%2Fvolt-vs-readout-resume.png)

## Why

#117 fixed the right structural problems — one page, claim selection, anti-filler voice — and then dressed them in a mid-century annual report: cream paper, Newsreader serif, a green rail printed down the page edge, an inset plate frame, diagonal newsprint grain, a folio. Every one of those signals *archive*. It also left the substrate that caused the original 3E failures in place: the three-page master résumé is still both the fact store and the layout, composition is still Cheerio surgery on a finished document, and the critic still hard-fails when an employer disappears.

So this pass redoes both halves.

**Visually:** white sheet on a near-black stage, Geist + JetBrains Mono (both already vendored in `vendor/fonts/fonts.css`, so materials inherit the app's own type system and ship zero new font binaries), one electric indigo accent used in five places, one column, whitespace as the primary material. Three signature moves and a spec that caps it at three: the caret after the name, the statement block with one highlighted clause, and verified metrics set in mono so numbers read as data. No serif, no cream, no texture, no frame, no chips, no charts.

**Mechanically:** facts move into a normalized `claim-ledger.json`, layout moves into dumb templates over `materials.render-model.v1`, and pagination moves into a deterministic fit solver with an ordered trim ladder. The single wide writer call becomes three narrow schema-bound calls (extract, select-by-ID, draft) plus a conditional anti-AI pass that never sees the posting. Every stage writes an inspectable artifact and appends to a `run.json` ledger.

## How

Notable decisions reviewers shouldn't have to re-derive:

- **Metric emphasis is generated, not authored.** The model emits plain strings; a deterministic tagger converts numerals into mono runs by matching claim-ledger metric tokens. The model can never emit markup, and a number it invented cannot be typeset as data — it fails `invented_fact` instead.
- **The letter rail is restated metadata only.** That is what keeps `cover-letter.txt` lossless and keeps a positional PDF parser from dropping information. The rule is in the spec and asserted in the test.
- **Budgets live in one module.** The 325-word letter floor existed in three places with two different values, which is how the padding QA then flagged got mandated. `server/materials-fit-budget.mjs` is now the only copy, and a contract test is planned for the drift.
- **Hermes becomes an executor, not an owner.** JobBored orchestrates; `local-inprocess` / `hermes-cli` / `webhook` satisfy stages behind one interface. Prompts, budgets, templates, and QA stay in one place, which is what stops the three-page template, the "≤ 2 pages" draft prompt, and the two-page quality gate from disagreeing.
- **No pin configured now produces something.** A degraded deterministic package publishes as REVIEW with `llm_unconfigured` instead of a 409, which also gives the suite a full-pipeline path with zero network.
- **Two modules landed rather than described.** `materials-fit-budget.mjs` and `materials-delint.mjs` + `materials-voice.json` are unwired; they exist so the two claims most worth doubting are executable. The fit test reproduces the trim decision `run.json` records, and the delint test asserts both directions: the letter opener the 3E dogfood actually produced fails on six codes, and the Volt mock is clean — which is why the run ledger shows the anti-AI call being skipped.

Docs are `docs/materials-v3/` (hub, side-by-side) plus `docs/superpowers/specs/2026-09-17-materials-v3-{volt,mechanism}-design.md` and `docs/superpowers/plans/2026-09-17-materials-v3.md`. The plan is nine slices and names the tests that must change on purpose.

## Anything reviewers should look extra carefully at?

Two places where I picked one option over another and could be talked out of it:

1. **The claim ledger replaces the master résumé HTML as the fact store.** #117 chose to keep that file and rename it "claim bank" in a comment. I think that is the load-bearing mistake: as long as facts and layout live in the same artifact, omission is illegal and pagination is the model's problem. The cost is that slice 1 has to extend the résumé/LinkedIn ingest, which is real work before any visible payoff.
2. **The letter rail.** It is the most *llamativo* element and also the only one with an ATS argument against it. I constrained it to restated metadata and asserted that in the test, but `rail: off` is in the variant table if it still feels risky.

Also worth a look: the visual spec's forbidden list (§7) is written as a review rejection rather than a preference, and the `density: tight` knob is deliberately only reachable after the trim ladder has exhausted everything droppable. Both are there to stop the system drifting back toward ornament and 8pt type.
