## What this changes

The local discovery starter no longer stays alive as a zombie noop holder after a reused worker on `:8644` dies. It re-probes `/health` every 5s and respawns so `npm run dev` keeps a real listener.

This is the 2026-09-16 Mac bring-up failure: starter PID alive for hours, **no child**, nothing listening on 8644, health checks connection-refused, while web `:8080` and scraper `:3847` stayed up.

## Why

`holdProcessOpenForExistingWorker` kept the concurrently child alive with `setInterval(() => {}, 60_000)` and only exited on SIGINT/SIGTERM. It never watched the reused worker.

That path is taken when:

1. A healthy worker is reused (or `--restart-existing` cannot terminate it).
2. The supervised child is SIGTERM'd by full-boot / keep-alive / autostart and a replacement answers `/health` within 8s.

If that listener later disappears, the starter used to sit there forever. Dashboard trials then fail at the TCP layer before sheet/secret/LLM checks.

## How

- New policy: `decideHeldWorkerAction({ heldWorkerHealthy, shuttingDown })` → `keep_holding` | `respawn` | `exit`.
- Hold now probes `/health` every 5s. Unhealthy → respawn via `superviseWorker` / `spawnOnce`. Ctrl-C / concurrently teardown still exits.
- After a long healthy hold, respawn counters reset (this is a new death, not a SIGTERM storm).

**Not in this PR** (config, not a starter bug):

- Placeholder `sheetId: "YOUR_SHEET_ID_HERE"` is refused at webhook preflight (`400`, "no Google Sheet is connected") when the request also has no real sheet id.
- Missing `integrations/browser-use-discovery/.env` / `server/.env` in the worktree does **not** by itself explain connection refused. Runtime secrets often live in `~/.jobbored/browser-use-discovery/.env`. An empty webhook secret fail-closes later with `401 no_secret_configured`.
- Bare `curl` to `/__proxy/local-health` and `/__proxy/start-discovery-worker` returning `{"ok":false,"reason":"forbidden"}` is the CSRF/origin guard. Same-origin browser fetches (Origin or `Sec-Fetch-Site: same-origin`) are allowed.

## Local recovery checklist (Emilio's Mac worktree)

Do **not** paste real sheet IDs, webhook secrets, or API keys into chat or commits.

1. Confirm the zombie: starter alive, no listener.
   ```bash
   lsof -nP -iTCP:8644 -sTCP:LISTEN
   curl -sS -m 2 http://127.0.0.1:8644/health || echo "8644 down"
   ```
2. Kill only the discovery starter / leftover worker, not the whole laptop:
   ```bash
   pkill -f start-discovery-worker-local.mjs || true
   pkill -f 'integrations/browser-use-discovery/src/server.ts' || true
   ```
   If `npm run dev` is still up, `concurrently -k` may tear web+scraper when the discovery child dies. If that happens, restart `npm run dev`.
3. After this PR: watch the starter log for `reusing existing process (will respawn if it dies)` and later `is no longer healthy; respawning` plus `[browser-use-discovery] listening on http://127.0.0.1:8644`.
4. Health from the dashboard tab (not bare curl):
   ```bash
   curl -sS -D- "http://127.0.0.1:8080/__proxy/local-health?port=8644" \
     -H "Sec-Fetch-Site: same-origin" \
     -H "Referer: http://127.0.0.1:8080/"
   ```
5. Config that still blocks a **successful trial** after the listener is back:
   - Real sheet in the dashboard (`config.js` / Settings), not `YOUR_SHEET_ID_HERE`.
   - Check **both** `integrations/browser-use-discovery/state/worker-config.json` (shipped template) **and** `~/.jobbored/browser-use-discovery/worker-config.json` (runtime default).
   - Secret + keys: `~/.jobbored/browser-use-discovery/.env` and/or worktree `.env` (gitignored). Worker fail-closes with `401` if `BROWSER_USE_DISCOVERY_WEBHOOK_SECRET` is empty. `discovery-local-bootstrap.json` should match that secret (do not commit it).
   - Signed-in Google access token on the run payload can satisfy Sheets writes even without a service-account file.
   - LLM pin (`~/.jobbored/llm.json` or worker LLM env) is required for scout/score; missing keys fail **after** 202 ack, not at listen.
6. `npm run doctor` (or `doctor:all`) for a red/yellow map without dumping secrets.

## Anything reviewers should look extra carefully at?

`holdProcessOpenForExistingWorker` now takes `onWorkerGone`. Top-level reuse/failed-restart calls `superviseWorker`; the in-supervisor hold path calls `spawnOnce` so we do not register a second supervisor. Crash-with-exit-code (no signal) still exits the starter and can take down `concurrently -k` — that is the 2026-09-02 policy, not this bug. I left it alone.
