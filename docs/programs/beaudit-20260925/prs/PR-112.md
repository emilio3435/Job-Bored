#112 cursor/scribe-empty-draft-guard-33c5
fix: guard empty AI drafts in scribe generate and refine

<!-- CURSOR_AGENT_PR_BODY_BEGIN -->
What’s fixed

- Prevent blank drafts: Treat an empty AI response as a failure for both initial generate and refine. The modal now shows a clear error message instead of rendering a blank preview that looks like success.
- Skip saving empty versions: Do not write empty text to the local draft library, avoiding silent creation of unusable versions.
- Scribe ↔ legacy truth preserved: These changes keep `#resumeGenerateOutput` as the source of truth; they only affect how empty results are handled before we mirror/preview/save.

Why this matters

- Dogfooding surfaced cases (esp. some providers or misconfig) where the model would return only the insights sentinel or an otherwise-empty body. Previously, that opened the modal with no body text (“blank output”), which looked like success but led to dead-ends for copy/print/refine.
- Refinements that produced no body text were being treated as successful updates. Now they report an actionable failure and preserve the current draft.

User-visible behavior

- Generate (Cover letter | Resume):
  - If the provider returns an empty body, the modal shows “The AI provider returned an empty draft. Adjust your instructions and try again, or switch providers in Settings.” No draft is saved.
- Refine:
  - If the refinement returns an empty body, the modal shows “Refinement returned an empty draft. Keep or adjust your feedback and try again.” The previous content remains.

Scope of change

- File: `resume-generation.js`
  - After `generateFromBundle(...)`, guard `cleanText` and throw a descriptive error when empty.
  - Do not attempt to save a draft when the generated/refined text is empty.
  - Leave ATS scorecard refresh, Scribe editor mirroring, and events untouched.

How to verify locally

1) Setup prerequisites
- Open the app (`npm start`) so both web and local API are available at `http://localhost:8080` and `http://127.0.0.1:3847`.
- Configure an AI provider in Settings. Easiest dogfood paths:
  - OpenRouter — paste a free key and keep a `:free` model.
  - Local (Ollama) — start Ollama and pull a text-only model like `gemma4:e2b`.
  - Gemini — paste a key from Google AI Studio.
- Add basic profile materials: paste a short resume in Portfolio; optional LinkedIn and AI context improve results.

2) Cover letter and resume generation
- From a pipeline card, click Tailor resume or use Scribe’s Cover letter | Resume tabs.
- Enter brief notes if desired and click Generate.
- Expect a non-empty draft body to render, copy/print enabled, ATS panel visible once scoring returns.

3) Empty-output edge case
- Temporarily misconfigure the provider (e.g., switch to a retired/free-tier model known to fail or simulate a webhook returning only the JSON sentinel without body text).
- Click Generate.
- Expected: The modal shows the new error message and no draft is saved; no blank preview.

4) Refine flow
- Type some feedback and click Refine.
- With a working provider: updated non-empty draft appears; versions/history updates.
- With a simulated empty refinement: the modal shows the new refine error message and preserves the prior draft.

Automated tests
- Existing unit/contract suites for bundle building, provider calls, and Scribe behavior still pass locally.
- These UX guards are minimal and isolated; they do not modify scoring, state stores, or data contracts.

Known prerequisites and environment notes
- A configured AI provider is required for generation (OpenRouter/gemini/local/webhook). Without it, the app already surfaces a gating toast pointing to Settings.
- ATS scoring requires the local server or a webhook; on GitHub Pages HTTPS, calling a local HTTP server is blocked by the browser (the UI already surfaces this with guidance).

No Discovery-wizard or MyUI+/CDLE scope touched.
