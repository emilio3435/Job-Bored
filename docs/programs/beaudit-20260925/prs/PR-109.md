#109 cursor/partial-zeros-error-502d
fix(discovery): Partial-with-zeros writes a concrete Error instead of a blank cell

<!-- CURSOR_AGENT_PR_BODY_BEGIN -->
## What this changes

A manual discovery run that finishes **Partial** with 0 companies / 0 leads / 0 updated now writes a concrete **ERROR** (and a worker log) instead of a blank cell. If Browser Use is missing, the worker no longer spends minutes on a Gemini scout that cannot be exploited.

## Why

Local dogfood on 2026-09-16 (~11:41–11:42 AM America/Chicago) showed two consecutive Manual `worker` runs:

- Sep 16, 11:42 AM — Partial — 2m 44s — 0 / 0 / 0 — variation `8df3036921415e00` — ERROR blank
- Sep 16, 11:41 AM — Partial — 2m 42s — same zeros — variation `5dc2afe5b8667fa6` — ERROR blank

That is the silent soft-fail path, verified in code (not guessed from the screenshot):

1. `runDiscovery()` marks **Partial** whenever 0 leads were written and **any** warning exists (`determineLifecycleState`).
2. It only copied `writeResult.writeError` into the DiscoveryRuns Error column. Warnings and `classifyFailureReason().reasonMessage` were computed **after** the log write and never persisted.
3. `buildDiscoveryRunLogRowFromStatus()` (watchdog / status-finalizer path) did the same: `error: status.error || ""`. The safety timer set `status: "partial"` and a duration message, but never `error`.
4. After local wizard onboarding, stored `companies` is `[]`. Unrestricted grounded search is allowed when intent is present. `grounded_web` exploit requires a Browser Use session manager. If Gemini search exists but Browser Use does not, the scout still ran (up to `groundedSearchTuning.maxRuntimeMs`, 180s on `browser_plus_ats`) and then soft-failed with a warning — Partial, zeros, blank ERROR. That matches the ~2m 42s–2m 44s pair.

This does **not** invent leads when Gemini / Browser Use / SerpApi / sheet auth are missing. Missing-key SerpApi stays optional (diagnostic only, not Partial) when it is the only lane. A valid setup that can actually extract still writes Pipeline rows as before.

## How

- Shared `resolveDiscoveryRunLogError()` fills the Error cell from, in order: sheet write error, explicit status.error, a missing-requirement warning (Gemini, Browser Use, empty companies, duration cap), classified `reasonMessage`, any other warning, then the status message.
- `runDiscovery()` classifies the failure **before** appending the DiscoveryRuns row and emits `discovery.run.partial_reason`.
- Grounded scout is skipped unless both `groundedSearchClient` and `browserSessionManager` are present, so a post-wizard run fails fast with “Browser Use session manager is unavailable” instead of cooking for minutes.
- Safety-timer Partial rows now carry the duration message in `error`.

### Local dogfood checklist

1. Finish the local wizard (worker + Tailscale/tunnel) with a real Sheet and non-blank intent (`targetRoles` or `keywordsInclude`).
2. Click **Run discovery**.
3. Open Discovery runs.
4. **Valid keys** (Gemini + Browser Use and/or SerpApi): expect Success (or Partial with a non-blank Error if a lane degraded) and `Leads New` / `Leads Updated` > 0 when jobs exist.
5. **Missing Browser Use or Gemini** after onboarding: expect Partial **quickly**, Error naming the missing client (not a blank cell, not a 2+ minute cook), companies may still be 0 if the worker catalog is empty.
6. Worker log should include `discovery.run.partial_reason` with the same Error text.
7. Watchdog / stuck-run: Error should mention exceeded maximum duration.

## Anything reviewers should look extra carefully at?

- `resolveDiscoveryRunLogError` prefers missing-requirement warnings over the generic `unknown` reasonMessage so the sheet cell stays under 200 chars and actionable.
- SerpApi without a key is still **not** a Partial by itself (`runDiscovery treats missing optional SerpApi key as unavailable without partial warning`).
- Companies Seen remaining 0 on unrestricted fallback is existing contract (`companyAllowlist` only restricts the stored catalog; empty local catalog + `allowUnrestrictedFallback` searches unrestricted). This PR does not re-seed the catalog from the dashboard allowlist.
