# JobBored for Mac: 0.1.0 → 0.1.1 update runbook

## What is confirmed before the release

The published [0.1.0 release](https://github.com/emilio3435/jobbored-desktop/releases/tag/desktop-v0.1.0) is marked **Latest** and lists `JobBored-0.1.0-universal-mac.zip` (259 MB), `JobBored-0.1.0-universal.dmg` (258 MB), and `latest-mac.yml` (361 bytes). It lists no `.blockmap` asset. That absence does not prevent this first update: electron-updater 6.8.9 [requires a ZIP on macOS and falls back to a full ZIP download when there is no cached prior update](https://github.com/electron-userland/electron-builder/blob/electron-updater@6.8.9/packages/electron-updater/src/MacUpdater.ts#L874-L973). The 0.1.1 workflow now checks and uploads the ZIP blockmap for later differential downloads.

The `desktop-v0.1.0` / `desktop-v0.1.1` tags match this updater. With prereleases off, its [GitHub provider reads the published latest release's actual tag, then downloads `latest-mac.yml` under that tag](https://github.com/electron-userland/electron-builder/blob/electron-updater@6.8.9/packages/electron-updater/src/providers/GitHubProvider.ts#L837-L1055). `vPrefixedTagName` governs electron-builder's own GitHub publishing tag; this workflow creates the draft with an explicit `desktop-v<version>` tag. The normal channel on macOS is `latest-mac.yml`.

The manual workflow input `version=0.1.1` becomes `VERSION` in the build command's `-c.extraMetadata.version="$VERSION"`. The new build gate reads the packaged `CFBundleShortVersionString` and compares it with `0.1.1`; it also checks the ZIP name, size, SHA-512 and blockmap against `latest-mac.yml`. The root package version and checked-in desktop package version remain `0.1.0`; the release build overrides the **packaged** version. This Mac has no `JobBored.app` directly in `/Applications` or `~/Applications` as checked on 2026-09-27, so a real installed-app update has not yet been run here.

## Emilio's release and update steps

1. After the MACUPD commit is integrated into `main`, download `JobBored-0.1.0-universal.dmg` from the [published 0.1.0 release](https://github.com/emilio3435/jobbored-desktop/releases/tag/desktop-v0.1.0), drag `JobBored.app` into `/Applications`, and open it. Keep this 0.1.0 installation in place for the update trial. If macOS says a copy is already running, quit it from its menu-bar icon first.
2. From a terminal with GitHub access, start exactly one 0.1.1 build: `gh workflow run desktop-mac.yml --repo emilio3435/Job-Bored --ref main -f version=0.1.1`. In `emilio3435/Job-Bored` → **Actions** → **Desktop (macOS)**, open that run. Wait for `build-mac` and `draft-release` to succeed. In particular, `Verify update payload matches the release version` must print `0.1.1: packaged app, update zip, blockmap and latest-mac.yml agree`.
3. Open `emilio3435/jobbored-desktop` → **Releases** → draft **JobBored 0.1.1** (`desktop-v0.1.1`). Confirm it contains the 0.1.1 DMG, 0.1.1 ZIP, matching `.zip.blockmap`, and `latest-mac.yml`. Read the manifest: `version: 0.1.1` and its `files` entry names the 0.1.1 ZIP. If the gate or draft differs, leave the draft unpublished and fix the build.
4. On that draft, click **Edit**, leave **Set as a pre-release** unchecked, select **Set as the latest release**, then click **Publish release**. This is the switch that exposes 0.1.1 to installed apps; drafts are invisible to electron-updater.
5. On the Mac running 0.1.0, open the JobBored briefcase menu-bar icon and choose **Check for updates**. The menu should show **Checking for updates…**, then **Downloading update (0.1.1)…**, then **Restart to update (0.1.1)**. Click **Restart to update (0.1.1)** and let the app relaunch. Automatic checks also run at launch and every six hours.
6. Confirm the new launch in `~/.jobbored/logs/desktop.log` (or choose **Open logs** in the tray). Look for `updater: checking`, `updater: downloading 0.1.1`, `updater: ready 0.1.1`, followed after the restart by `JobBored 0.1.1 starting (packaged)`. The successful result is an installed 0.1.1 app whose dashboard and local services run normally. If the tray shows **Update failed — Check for updates**, click it to retry and read the same log for the error.

The live 0.1.0 → 0.1.1 install is still an external release check. No workflow was dispatched and no draft was published while preparing this runbook.
