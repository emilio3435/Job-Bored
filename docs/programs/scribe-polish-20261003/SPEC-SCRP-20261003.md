## §3 Frozen contracts (D7) — amended after the Fable plan check (`reports/VERDICT-SCRP-PLAN.md`); where the original text below conflicts with §3A, §3A wins

### §3A Amendments (binding)
- **C1:**
  - The stored proposal uses `id` and is projected as `proposalId`. The stored `doc` is always `resume | coverLetter`, while the client uses `cover_letter`, so FE maps between them.
  - `blocked` is derived from the stored `events` (rows with type `blocked`). `events`, `targetPages` and `chips` are never projected.
  - GET open uses a **read-only** scan: no `sweep`, no folder creation, expired rows (>7 d) treated as absent, a missing `proposals/` folder tolerated.
  - GET open honors `pending.json` like every other route (409 `materials_pending`), and BE adds it to the existing pending-table test.
  - The `multiple_open_proposals` 409 is written by the route handler with `res.status(409).json(...)`, not thrown.
  - The client method is `getOpenEdit()`, since the client is slug-bound. A missing method, a 404 or a network failure is non-fatal: the desk opens as today.
- **C1b (reprocess):** when a stream attaches to a `pending` proposal that already has events (after a restart or Continue), BE resets `ops` and `events` before reprocessing, so opIds stay unique and there is exactly one `done`.
- **C2 is a client contract** (no server change). After the client's existing single stale-base retry (`scribe-v2-api.js` `withStaleBaseRetry`), FE calls `getModel(rebasedTo)` and `preview({doc, baseRunId: rebasedTo})` and installs that exact base before the stream and marks. BE drops C2.
- **C3:**
  - Predicate: `status===503 && code==="browser_unavailable" && typeof run.runId==="string" && run.runId && run.pdf==="stale"`.
  - BE adds `n` and `versions` to the restore 503/200 body (additive) and sets `retryable:false` on every committed-503 body (accept, manual, restore). The envelope in `server/index.mjs` respects an explicit boolean.
  - FE never retries when `textSaved`.
  - BE removes only the PDFs of the rendered documents on that path; the sibling PDF survives (verdict #34, red-first).
- **C4 = `schemas/api-error.v1.schema.json`** (`error, code, detail?, nextStep?, retryable`). The client shows `message || error`, sets `fix = body.fix || body.nextStep`, and keeps `detail`, `retryable`, `status` and `code`.
- **C4b (writer channel):**
  - Writer outcomes reach the client as **SSE `blocked` rows** `{reason, detail}`. The reasons are `provider_failed` | `unreadable_reply` | `invalid_model`, plus the existing `locked`/`out_of_scope`/`shape`. Each carries a fixed safe `detail`.
  - Thrown failures reach the client as **SSE `error` `{code, message}`**, where `message` is a fixed per-code string. The raw `error.message`, filesystem paths and payloads are never sent. FE maps SSE `error.code` as well.
  - The writer codes map as follows:

  | Writer code | Maps to |
  |---|---|
  | `network`, `timeout`, `http_5xx`, `http_*` | `provider_failed` |
  | `http_429` | `rate_limited` |
  | `invalid_json`, `schema_invalid` | `unreadable_reply` |
  | `writer_truncated` | `reply_cut_off` |
  | `writer_blocked` | `provider_refused` |
  | `no_pin`, `llm_unconfigured` | `llm_unconfigured` |
  | applyOps rejection | `invalid_model` |

  - The route limiter's 429 `rate_limited`/`too_many_in_flight` on POST edits, manual, accept and restore are HTTP errors that FE maps.
  - BE records the final table in CONTRACT-CHANGELOG.md.
- **materials_pending has three causes:** generation running (`pending.json`), an in-flight edit claim, and an open proposal. FE rule: on a 409 `materials_pending`, call GET open **once**. A proposal → recover. `null` or a 409 → "JobBored is still working on this role. Try again in a moment." Never loop.
- **C5:** the request shape is unchanged. BE adds the 409 `materials_pending` guard for a persisted open proposal.
- **C6:** the red run must be the strict `doneStatuses` assertion failing with `[partial, ready]`, not a missing-seam TypeError.

**C1 GET open proposal.** Route: `GET /api/applications/:slug/edits/open`, mounted in `registerMaterialsEditRoutes`, inheriting the existing auth, path and CORS.
- No open proposal: `200 {"proposal":null}`.
- One open proposal:
  ```
  200 {"proposal":{"proposalId","doc":"resume"|"coverLetter","baseRunId","instruction","scope","lockFacts":true,"createdAt",
       "status":"pending"|"ready"|"partial"|"accepting","ops":[…validated],"blocked":[…],"summary"?,"factCheck"?,"factCheckReason"?}}
  ```
  `doc` is the stored proposal's document name exactly as POST /edits persists it (`documentName()` accepts `resume`, `coverLetter`, `cover_letter`); BE records the emitted value in CONTRACT-CHANGELOG.md.
- Eligibility follows the role gate: pending or accepting, or ready/partial with nonempty ops. It excludes accepted, failed, rejected and empty terminal proposals.
- More than one open file: `409 {"error","code":"multiple_open_proposals","proposals":[{"proposalId","doc","status"}]}`.
- The response projects safe fields only, with no paths, profile, ledger, handles or secrets. The read is side-effect free.
- Client: `api.getOpenEdit(slug)` in `scribe-v2-api.js`. The stub answers only when the stub is explicitly selected; live stays the default.

**C2 Rebased start.** When POST /edits does its one permitted stale-base retry, the 202 body adds
`"rebasedTo":"<runId>","rebase":{"listing":{…same shape as GET versions…},"model":{…},"nodes":{…},"preview":{"html","words","pageBudget"}}` for exactly `listing.currentRunId === rebasedTo`. A second concurrent move returns 409 `stale_base`.

**C3 Committed 503.** Accept, manual and restore return 503 with `code:"browser_unavailable"`, a valid nonempty `run.runId`, `run.pdf.stale===true` (or the endpoint's existing equivalent field) and the endpoint metadata. The client resolves this as `{...body, textSaved:true, httpStatus:503}`. Any other 503 rejects as before.

**C4 Error shape.** Bodies are `{error:string, code:string, message?:string, fix?:string}`. The client shows `message`, then `error`, then a fallback, each bounded to 300 characters, rendered with textContent, and keeps `status`, `code` and `fix`. The writer distinguishes three codes, each without raw payloads: `provider_failed` (transport or provider error), `unreadable_reply` (malformed, absent or non-JSON ops) and `invalid_model` (a real applyOps/template violation). BE records the exact codes in CONTRACT-CHANGELOG.md.

**C5 Manual write.** Request: `POST …/edits/manual {doc,baseRunId,manualOps:[{opId,op:"replace",node,text}],confirmUnverified:[opId]}`. It now also returns 409 `materials_pending` when the role has a persisted open proposal (second-tab ownership), while keeping the CAS `stale_base` and the existing fact gates.

**C6 Terminal ownership (R0).** A proposal leaves `pending` exactly once through a synchronous claim. Persistence and SSE delivery are serialized per proposal, and there is exactly one terminal `done`. The optional `persistProposal(path, snapshot)` service dependency and a non-awaited transition observer exist for tests only.
