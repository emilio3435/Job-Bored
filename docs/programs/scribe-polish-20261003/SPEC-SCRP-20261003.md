## §3 Frozen contracts (D7)

**C1 GET open proposal.** Route: `GET /api/applications/:slug/edits/open`, mounted in `registerMaterialsEditRoutes`, inheriting the existing auth, path and CORS.
- No open proposal: `200 {"proposal":null}`.
- One open proposal:
  ```
  200 {"proposal":{"proposalId","doc":"resume"|"coverLetter","baseRunId","instruction","scope","lockFacts":true,"createdAt",
       "status":"pending"|"ready"|"partial"|"accepting","ops":[…validated],"blocked":[…],"summary"?,"factCheck"?,"factCheckReason"?}}
  ```
  `doc` is the stored proposal's document name exactly as POST /edits persists it (`documentName()` accepts `resume`, `coverLetter`, `cover_letter`); BE records the emitted value in CONTRACT-CHANGELOG.md.
- Eligibility follows the role gate: pending or accepting, or ready/partial with nonempty ops. It excludes accepted, failed, rejected and empty terminal proposals.
- More than one open file: `409 {"error","code":"multiple_open_proposals","proposals":[{"proposalId","doc","status"}]}`.
- The response projects safe fields only, with no paths, profile, ledger, handles or secrets. The read is side-effect free.
- Client: `api.getOpenEdit(slug)` in `scribe-v2-api.js`. The stub answers only when the stub is explicitly selected; live stays the default.

**C2 Rebased start.** When POST /edits does its one permitted stale-base retry, the 202 body adds
`"rebasedTo":"<runId>","rebase":{"listing":{…same shape as GET versions…},"model":{…},"nodes":{…},"preview":{"html","words","pageBudget"}}` for exactly `listing.currentRunId === rebasedTo`. A second concurrent move returns 409 `stale_base`.

**C3 Committed 503.** Accept, manual and restore return 503 with `code:"browser_unavailable"`, a valid nonempty `run.runId`, `run.pdf.stale===true` (or the endpoint's existing equivalent field) and the endpoint metadata. The client resolves this as `{...body, textSaved:true, httpStatus:503}`. Any other 503 rejects as before.

**C4 Error shape.** Bodies are `{error:string, code:string, message?:string, fix?:string}`. The client shows `message`, then `error`, then a fallback, each bounded to 300 characters, rendered with textContent, and keeps `status`, `code` and `fix`. The writer distinguishes three codes, each without raw payloads: `provider_failed` (transport or provider error), `unreadable_reply` (malformed, absent or non-JSON ops) and `invalid_model` (a real applyOps/template violation). BE records the exact codes in CONTRACT-CHANGELOG.md.

**C5 Manual write.** Request: `POST …/edits/manual {doc,baseRunId,manualOps:[{opId,op:"replace",node,text}],confirmUnverified:[opId]}`. It now also returns 409 `materials_pending` when the role has a persisted open proposal (second-tab ownership), while keeping the CAS `stale_base` and the existing fact gates.

**C6 Terminal ownership (R0).** A proposal leaves `pending` exactly once through a synchronous claim. Persistence and SSE delivery are serialized per proposal, and there is exactly one terminal `done`. The optional `persistProposal(path, snapshot)` service dependency and a non-awaited transition observer exist for tests only.
