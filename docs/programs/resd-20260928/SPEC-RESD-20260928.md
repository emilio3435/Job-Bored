# RESD — Dossier resume evidence repair

Goal: Make a Dossier resume draft use source-grounded, correctly attributed experience and explain any selected evidence excluded by the page budget.

Success means:
- Fictional split-header, two-column, unbulleted, and conventional resumes produce grounded employer and claim associations; poisoned and ambiguous inputs remain rejected.
- A failed or sparse interpretation of the current resume stops the new draft with a clear recovery message while preserving the last successful package.
- Every selected claim is featured, earlier, or counted as a page-budget exclusion; the Dossier shows the exclusion count from the saved run.
- The focused and full repository floors pass on the integration branch, followed by privacy-safe local run verification when a configured provider is available.

Stop when: The integrated branch is verified and locally committed, with reports and any unavailable provider/browser checks named; or a repeated access or provider blocker prevents the required acceptance check.

## Evidence and architecture

Read `../resume-dossier-20260928/{SOL-DIAGNOSIS-PLAN,RUNS-LUNA,CODE-LUNA}.md`. The newest saved resumes load a ledger with 21 claims and two employers, but every claim points to one employer; `model_sparse` appears before `claims.load`. Selection keeps nine, while one featured employer uses five and records four `page_budget` exclusions. A prior control with a different ledger uses two featured employers and two earlier lines.

The shared substrate is the saved resume source and `ensureLedger`: the model interprets the source, the validator grounds values and associations, the ledger records source identity and status, and `createMaterialsDrafter` gates the pipeline on that status. `runPipeline` owns selection and outline accounting, publishes a count-only summary in `run.json`, and `readApplicationManifest` exposes it to the Dossier. The Dossier reads that summary after publication. Current `origin/main` already passes posting outcomes into `materials-draft.mjs`, so the prompt gap in the older checkout is not an implementation fence here.

## Backend contract

- `ensureLedger` returns `ingest.status: ready | failed | not_required`, an input-bound resume source hash, a stable failure code, and count-only coverage: total employers, employers with attributed claims, and rejected/loose claim counts. A model error, invalid reply, or unsupported employer attribution is `failed`; the saved last-good ledger remains available for old packages. A two-employer source with substantive claims for both cannot pass with all claims assigned to one.
- `createMaterialsDrafter` checks that the current request's resume hash and ledger source match and that `ingest.status` is ready before calling `runPipeline`. A failed check writes the existing failed-pending path with code `resume_source_review` and a recovery message. No new run package is published.
- `runPipeline` records `selectionSummary: { selected, featured, earlier, pageBudgetExcluded }` for resumes in `run.json`. The accounting partitions `selection.kept` by claim ID exactly once; empty/unknown IDs are a structural error, not a success count.
- `readApplicationManifest` copies `selectionSummary` for the current published run. Legacy manifests omit it. The Dossier renders an exclusion note only when `pageBudgetExcluded > 0` and a resume document exists.
- `resume_source_review` is delivered through the existing `pending.progress.code` field and an inline Dossier state with Retry and Open Resume actions. It carries no source text, raw model reply, or personal facts.

## Red-first claims

- `R1` A fictional split-header/two-column source preserves two distinct source-backed employers and each claim's supported employer/role; a deliberately cross-assigned source quote is rejected or review-gated.
- `R2` A model reply with an invented employer, unrelated quote, or poisoned instruction is rejected; no prior ledger claim is silently relabeled.
- `R3` A current-source model failure with a prior ledger produces `pending.progress.code=resume_source_review`, zero new pipeline calls, and an unchanged prior package.
- `R4` Selected IDs partition into featured, earlier, and `page_budget` exactly once; a two-employer fixture can feature both when within the page budget.
- `R5` The current run's count-only summary reaches the Dossier; a legacy manifest and a zero-exclusion run show no exclusion note.
